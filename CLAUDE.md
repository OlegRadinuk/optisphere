# Optisphere — Project Context

## Суть проекта
Сайт веб-студии **Optisphere / Оптисфера** (соло, позиционируется как студия). Владелец — Олег.
**Главная задача: КОНВЕРСИЯ В КЛИЕНТА** — не просто красиво, а продаёт.

Позиционирование: "Мы не делаем просто сайты — мы создаём сайты, которые приносят клиентов."

## Приоритет
1. Конверсия
2. Скорость
3. UX
4. Визуал

**Конверсия > Визуальные эффекты** — если что-то тормозит, путает или не ведёт к заявке → убрать/упростить.

## Целевая аудитория
Гостиницы/апартаменты, строительные компании, медицинские клиники, малый и средний бизнес.

SEO + Яндекс.Директ — часть подписки PRO/MAX.

## Структура сайта (воронка)
1. **Hero** — сфера + УТП + стартовые цены
2. **Услуги** — три "мира" при скролле: Сайты (#4F8EFF) → Панорамы (#C9A96E) → Продвижение (#3ECFA0)
3. **Портфолио** — фильтр по типу, живые ссылки + цена такого сайта
4. **Цены** — диапазоны, не точные
5. **Калькулятор** — показывает диапазон (60–120к / 120–180к), после → подключается Юра
6. **Подписка "Орбита"** — выделенный блок
7. **Доверие** — кейсы с цифрами, отзывы, логотипы клиентов (стилизованы как "космический флот")
8. **CTA** — быстро, без трений
9. **Юра** — финальный дожим

## Воронка пользователя
1. Зашёл → 3D WOW (0–5 сек)
2. Понял что это → быстро (услуги через планеты)
3. Доверие → портфолио + цифры
4. Цена → диапазон + калькулятор
5. Контакт → Юра закрывает

## AI-ассистент "Юра"
- Появляется НЕ сразу — после задержки/скролла
- Роль: консультант + квалификатор + продавец
- Задаёт 1–2 вопроса → даёт пользу → предлагает помощь → запрашивает контакт
- **Иногда рассказывает факт о космосе** — характер, не просто скрипт продажника
- **Финальная реплика клозера:** "Ну что, делаем?" — прямо и по делу
- **Обязательная цель: получить контакт** (Telegram / телефон)
- Отправляет диалог + summary + intent (горячий/тёплый/холодный) в Telegram
- Личность: уверенный, умный, слегка неформальный, не навязчивый
- Визуал: стеклянная сфера / energy core, анимация, в тему космоса
- Claude API (claude-haiku-4-5 для скорости/стоимости, claude-sonnet-4-6 для качества)

## 3D и визуальная концепция
- **Тема: космос** — тёмный фон (#07070F), звёздное поле, сфера как небесное тело
- **Иконки заменяем на планеты** — Mars, Venus и другие для сервисов/фич
- Сфера в Hero — навигация + объяснение услуг + эмоциональный крюк (НЕ просто декорация)
- Орбитальные планеты: hover → карточка, клик → скролл к секции
- **Hero — единственная тяжёлая 3D сцена**, остальное — лёгкое
- Loader: ракета летит → прилетает к сфере (0.8–1.2с, без излишеств)
- **Звуки**: мягкие космические ambient звуки — рассмотреть (включаются по желанию, не автоматом)

## Mobile стратегия (КРИТИЧНО)
Mobile — оптимизированная версия, НЕ упрощённая скучная.
- Tap вместо drag
- Меньше физики и шейдеров
- Та же структура, проще реализация
- Больше CTA

## Performance (КРИТИЧНО)
- First meaningful paint < 1.5s
- Initial load ≤ 3MB
- Только Hero использует тяжёлый WebGL
- Lazy load всего тяжёлого
- UI должен появиться ДО полной загрузки 3D
- Расчёт на слабый интернет и мобильные устройства

## Tech Stack
- Next.js 16 (App Router) — читать `node_modules/next/dist/docs/` перед использованием routing/API

## i18n
- Весь текст только в `messages/ru.json` / `messages/en.json` — NO hardcoded text
- Переключатель языка в navbar
- URLs: `/` = RU, `/en/` = EN

## Next.js 16 breaking changes
- `middleware.ts` → теперь `proxy.ts`
- Всегда проверять `node_modules/next/dist/docs/` перед использованием Next.js API

## Нельзя
- Хардкодить текст — только i18n ключи
- Использовать `any` в TypeScript
- Секреты в клиентских компонентах — только API routes
- Пропускать `loading` состояния
- `useEffect` для fetching — Server Components или React Query
