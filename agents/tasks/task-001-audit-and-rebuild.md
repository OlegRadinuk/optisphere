### Что анализировать по каждому файлу

**Код:**
- Есть ли дублирование логики между файлами?
- Есть ли `any` в TypeScript?
- Хардкодированный текст (не через i18n)?
- Сложность: можно ли понять что делает файл за 30 секунд?
- Мёртвый код (импорты, функции, переменные которые не используются)?

**Архитектура:**
- Правильно ли разделены Server/Client компоненты?
- Есть ли нарушения App Router паттернов?
- Насколько компоненты переиспользуемы vs монолитны?

**Performance:**
- Тяжёлые импорты в клиентском бандле?
- Lazy loading соблюдается?
- Что грузится без необходимости?

**Известный баг:**
```
Планеты в OrbitalSphere исчезают при hard refresh (Ctrl+F5) в dev режиме.
При client-side навигации (/ru→/en→/ru) всё работает нормально.
Гипотеза: React Strict Mode дважды монтирует компонент, второй маунт не инициализируется.
СНАЧАЛА: проверить есть ли баг в prod (npm run build && npm start).
Если нет — это dev/Strict Mode артефакт, не тратить время.
```

## ШАГ 2 — Решение (orchestrator, model: opus)

На основе отчёта аудита принять решение:

### Критерии для выбора ПЕРЕСОЗДАНИЕ (с нуля)
- OrbitalSphere.tsx содержит >50% мёртвого кода или нечитаем
- Архитектурные проблемы затрагивают >3 файлов
- Баг планет воспроизводится в prod и требует переработки R3F структуры
- Рефакторинг займёт столько же времени сколько написать заново

### Критерии для выбора РЕФАКТОРИНГ
- Код читаемый, проблемы точечные
- Баг только в dev (Strict Mode) — игнорируем
- Большинство файлов в состоянии "хорошо, нужно немного причесать"

### При решении ПЕРЕСОЗДАТЬ:
- OrbitalSphere.tsx используется как **референс** (идеи, шейдеры, логика планет)
- Старые файлы переименовать в `*.legacy.tsx` — не удалять, пока новые не работают
- Начать с архитектуры: что в каких файлах, как связаны

### При решении РЕФАКТОРИТЬ:
- Составить приоритетный список файлов
- Начать с самых проблемных
- Баг планет — проверить в prod, если нет → закрыть тикет
